## [0.3.6](https://github.com/lucasram20/artui/compare/v0.3.5...v0.3.6) (2026-05-23)

### Features

- **auth:** OpenAI ChatGPT subscription OAuth 2.0 PKCE login. `/login openai_account` opens the browser at `https://auth.openai.com/oauth/authorize` with the Codex CLI client_id (`app_EMoamEEZ73f0CkXaXp7hrann`), runs a loopback callback server on `127.0.0.1:1455` (fallback `1457`), validates `state` for CSRF, exchanges the code for tokens, parses the `id_token` JWT for `chatgpt_account_id`/`plan_type`/email, and persists everything via the shared `AuthStore` (provider id `openai_account`). Tokens auto-refresh on near-expiry. New `src/auth/openai_oauth.rs` with 13 unit tests.
- **providers:** Codex streaming via the ChatGPT-backend Responses API. The OpenAI Codex provider now POSTs to `https://chatgpt.com/backend-api/codex/responses` with `Authorization: Bearer <access_token>`, `ChatGPT-Account-Id`, and `OAI-Product-Sku: codex` headers, parsing `response.output_text.delta`, `response.refusal.delta`, `response.reasoning(_summary).delta`, `response.completed` (with usage), and `response.failed`/`incomplete`/`error` SSE events. Auto-refreshes the access token within 60s of expiry. Tool-call streaming is deferred to a follow-up — text-only first iteration. 7 unit tests for the SSE parser.
- **ui:** Dedicated *OpenAI Codex* section in `/model`. Curated, plan-agnostic Codex model list: `gpt-5.5`, `gpt-5.5-pro`, `gpt-5.5-codex`, `gpt-5.5-mini`, `gpt-5.4`, `gpt-5.4-codex`, `gpt-5.4-mini`, `gpt-5.4-nano`, `gpt-5.3-codex`, `gpt-5.2-codex`, `gpt-5.1-codex-mini`, `gpt-5-codex`, `gpt-4.1`, `gpt-4.1-mini`, `gpt-4.1-nano`. Free, Plus, Pro, Team, and Enterprise plans all see the same list; override via `providers.openai_account.default_model`.
- **ui:** `/login` picker now lists only `AuthRequirement::Account` providers (Copilot + OpenAI Codex). Ollama is local and `openai_compat` resolves credentials from environment variables, so neither has a meaningful login flow to surface.
- **ui:** Display name `OpenAI account` → `OpenAI Codex` to match the Codex CLI brand. Provider id stays `openai_account` so existing stored auth records keep working.
- **ui:** New `/mouse` slash command toggles in-app mouse capture. Default is **off** so the host terminal owns drag-select and clipboard copy on LLM responses, the input box, and everywhere else in the TUI — matching Claude Code, Codex CLI, and pi. Toggle via `/mouse` to enable in-app scroll wheel handling.
- **schema:** New `OpenAiAccountConfig` knobs: `oauth_client_id`, `oauth_issuer`, `oauth_scope`, `oauth_port`, `oauth_fallback_port`, `oauth_timeout_secs` (each defaults to the codex CLI value when blank). New `CopilotConfig.strict_picker` flag (default `false`).

### Bug Fixes

- **install:** `scripts/install.ps1` now parses on Windows PowerShell 5.1. The previous `param()` block used the `??` null-coalescing operator (PowerShell 7+ only), which caused `irm … | iex` to fail with `Missing ')' in function parameter list` for the default Windows shell. Replaced with `$(if ($env:VAR) { $env:VAR } else { 'default' })` expressions so the script works on both 5.1 and 7+. Hotfixed in place against 0.3.6 — no version bump.
- **copilot:** Show the full model list on student/free Copilot plans. Default ("relaxed") picker filtering now only excludes models with `policy.state = "disabled"`. The `model_picker_enabled` flag returned by `api.githubcopilot.com/models` is gated by per-plan rollout and was hiding callable models on student/free plans. Strict mode is preserved as an opt-in via `providers.copilot.strict_picker = true` for users who want to mirror the VS Code Copilot Chat picker exactly.
- **ui:** Mouse capture is no longer enabled at startup; without this fix, drag-select to copy text from the chat transcript and the input box was silently swallowed by the TUI. The runtime reconciles capture mode with `App.mouse_capture` each event-loop tick, so `/mouse` enables/disables capture lazily.

  - bash/PowerShell prompts default to "yes" but accept `n` to bail without downloading.
