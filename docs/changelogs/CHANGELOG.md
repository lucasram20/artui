# Changelog

All notable changes to artui will be documented in this file.
This file is generated by `semantic-release` from Conventional Commits.

## Unreleased

### Added

- **snapshots:** Workspace-level snapshots are enabled by default via `[snapshots]`, stored under `~/.local/share/artui/snapshots/<workspace_hash>/`, and retain the newest 20 entries unless configured otherwise.
- **snapshots:** Added git and tar backends: git workspaces capture tracked and untracked files as git trees; non-git workspaces use compressed `tar.zst` archives with a `max_tar_mb` guard.
- **agent:** Auto-snapshot before `apply_patch` and before non-read-only shell commands by default; optional `auto_per_turn` can snapshot at the start of every agent turn.
- **ui:** Added `/snapshot`, `/snapshot list`, `/snapshot restore <id>`, and `/snapshot clear` slash-command flows, plus a UI notice when an auto-snapshot is saved.
- **tests:** Added snapshot integration coverage for git capture/restore, tar fallback behavior, slash-command handling, and isolated snapshot storage.

### Changed

- **shell:** Added a read-only shell-command classifier so snapshot gating skips common inspection commands while still protecting mutating commands.
- **docs:** Consolidated docs/spec layout and added the Phase M3 snapshot design and implementation plan references.

## [0.6.1](https://github.com/lucasram20/artui/compare/v0.6.0...v0.6.1) (2026-05-31)

Pipeline-only release. v0.6.0 shipped the LSP N2/N3/N4 work cleanly but the GHA release workflow ran out of minutes mid-publish — all 6 binaries built fine and were attached to the release manually via `gh release create` from a downloaded artifact bundle. v0.6.1 is the first release cut through the new CircleCI pipeline so the chain is end-to-end automated again.

### Changed

- **Release pipeline moved to CircleCI.** `.circleci/config.yml` gains a `release` workflow with 6 cross-compile jobs (linux-x86_64/aarch64 via `cargo zigbuild` from x86_64, macos-x86_64/aarch64 via native ARM runner with `--target` cross, windows-x86_64/aarch64 via Windows runner with `--target`) and a `release-publish` job that runs after all 6, computes checksums, uploads to Cloudflare R2, and creates the GitHub release. Same artifact set as the old GHA pipeline, same R2 + GitHub release shape, just on a different runner pool. CI workflow unchanged.
- **GHA `release.yml` neutralized** to `workflow_dispatch` only. Renamed to "Release (fallback)". Tag pushes only trigger CircleCI now. The original tag-push trigger is kept as a comment in the YAML so re-enabling is a one-line revert if CircleCI is ever unavailable.
- **README release docs** updated to point at CircleCI for the primary release flow with GHA shown as the fallback path.

### Notes

- Required CircleCI project env vars (set before this release): `GITHUB_TOKEN` (Contents:Write), `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. Same shape as the GHA secrets the old `release.yml` used.
- 240 lib tests + 8 integration tests + 2 LSP integration tests still pass. No source code changed in this release — only CI and version-bump files.
- The R2 mirror was not refreshed for v0.6.0 (the R2 upload step was part of the failed publish job). v0.6.1's release pipeline mirrors both v0.6.0 and v0.6.1 archives to R2 if the upload-versioned-paths step finds them; in practice the v0.6.1 install one-liner will work end-to-end and v0.6.0 users should bump.

## [0.6.0](https://github.com/lucasram20/artui/compare/v0.5.0...v0.6.0) (2026-05-31)

Big release. Three things ship together:

1. **Phase N2 + N3 + N4 LSP work** — read-only completeness, writethrough on `apply_patch`, and mutating operations (rename + code_actions). The `lsp` tool now exposes 11 actions covering definition, references, hover, implementation, type_definition, document_symbols, workspace_symbols, diagnostics, rename, code_actions, and status.
2. **Claude-Code-style spinner header** — the streaming line now shows elapsed time and cumulative output tokens, e.g. `Working (12m 50s · ↓ 26.3k tokens · esc to interrupt)`. Lets you see at a glance how long the agent has been at it and how many tokens it's burning.
3. **Claude-Code-style todo list** — new `todo_write` tool the model calls to surface multi-step plans. Renders as a checklist in the chat pane with `[done/total tasks done]` header. Items are pending / in_progress / completed; only one can be in_progress at a time, enforced server-side.

### Added — LSP read-only completeness (Phase N2)

- **`lsp` references action**: `textDocument/references` with `includeDeclaration: true` (configurable). Returns ≤50 hits formatted as `path:line:col\n  preview` with the source line for context. Unscoped queries on common types (`Display`, `Iterator`) cap to 50 with a "narrow with workspace_symbols query" footer.
- **`lsp` implementation action**: `textDocument/implementation`. Resolves a trait/interface position to its concrete impls.
- **`lsp` type_definition action**: `textDocument/typeDefinition`. Resolves a value position to its declaring type.
- **`lsp` document_symbols action**: `textDocument/documentSymbol`. Tree-rendered output — `[struct] App\n  [fn] new\n  [fn] handle_event`. Walks both `Flat` and `Nested` server response variants.
- **`lsp` workspace_symbols action**: `workspace/symbol` driven by `query` arg. Falls back gracefully when no client is yet running with a "call definition or hover first" hint instead of force-spawning a fresh server.
- **`lsp` diagnostics action**: reads the cached `publishDiagnostics` map populated by server-pushed notifications. Optional `path` arg filters to one file; without it, returns every tracked file's diagnostics. Severity tags rendered as `[error]` / `[warn]` / `[info]` / `[hint]`.
- **`LspClient` notification routing**: `publishDiagnostics` notifications now flow into the `Mutex<HashMap<PathBuf, Vec<Diagnostic>>>` cache and emit `AppEvent::LspDiagnostics(server_id, path, count)` so the TUI footer can surface counts.

### Added — LSP writethrough (Phase N3)

- **`src/lsp/writethrough.rs`** — new module with `EditedFile`, `WritethroughOutcome`, and the `after_edit` entry point. Sends `didOpen` on first track, `didChange` on subsequent edits with bumped version. Polls `cached_diagnostics` until either a result lands or the configured timeout fires.
- **`apply_patch` integration**: every successful patch now runs the writethrough loop (when `[lsp] writethrough = true`). The tool result gains a trailing `── LSP diagnostics ── ...` block — `(clean)` when the file type-checks, the formatted diagnostics when it doesn't, `(timeout)` when the server didn't respond in time. Diagnostic scoping window is `±3 lines around changed lines` so pre-existing issues elsewhere in the file don't pollute the result. The `compute_changed_lines` helper diffs old/new content line-by-line and feeds the changed-line set to the renderer.
- **`LspClient::track` / `untrack` / `open_version`** — public surface for didOpen/didChange/didClose lifecycle. Per-file `version: i32` counter inside `OpenFile` state.
- **`LspConfig.writethrough` and `LspConfig.diagnostics_timeout_ms`** — new config knobs in `[lsp]`. Defaults `true` and `750ms`. Threaded through `ProviderRequest` → `AgentLoopConfig` → `ToolContext` so apply_patch can read them.
- The agent now sees its own breakage in the same turn it caused it. Edit → diagnostics → fix → clean — the headline feedback loop oh-my-pi pioneered.

### Added — LSP mutating ops (Phase N4)

- **`src/lsp/edits.rs`** — new module that applies `lsp_types::WorkspaceEdit` payloads to disk. `apply_workspace_edit` fan-outs to `apply_text_edits` per file, sorts edits descending by position so earlier offsets stay valid, walks UTF-16 code units to handle non-ASCII correctly, refuses writes outside the workspace root (path-traversal guard), and returns an `ApplyReport { applied, total, files }` so partial failures surface cleanly.
- **`lsp` rename action**: `textDocument/prepareRename` first to gate non-renameable positions, then `textDocument/rename` for the `WorkspaceEdit`. Routes through the approval engine — the agent sees an Ask modal in Build mode, Deny in Plan mode. Renders as a per-file edit-count summary so the user can see what's about to change before approving.
- **`lsp` code_actions action**: listing variant returns the menu (`[0] Add missing import`, `[1] Generate `is_x` method`, …) — read-only. Apply variant (with `apply: "<title>"`) takes a chosen action's `WorkspaceEdit` through the same approval path as rename. `executeCommand` server-side commands are explicitly out of scope and surface as a clear error.
- **`PermissionEngine::classify_lsp_call`** — new sub-classifier inspects `arguments.action` so the same `lsp` tool dispatcher can be Allow-class for read-only ops and Ask-class for mutations. `code_actions` listing (no `apply` arg) is correctly classified as read-only; only `code_actions` with `apply` is treated as a write.
- 7 new permission tests cover the classification matrix: read-only auto-allow, rename Ask in Build, rename Deny in Plan, code_actions listing read-only, code_actions apply Ask, unknown action falls through to Allow (so the tool's own validator can emit a friendly error), per-tool `[permissions.tools]` overrides short-circuit the sub-classifier.

### Added — Spinner header with elapsed time + token count

- **`format_elapsed`** in `ui/chat.rs` renders the active turn's wall-clock as `42s` / `12m 50s` / `1h 5m`. Drops seconds entirely past the hour to keep the header narrow.
- **`format_token_count`** renders cumulative output tokens as `780` / `4.2k` / `1.2M`. Round thousands drop the trailing `.0` for visual cleanliness (`5k`, `10k`, not `5.0k`, `10.0k`).
- **`App.turn_input_tokens` / `App.turn_output_tokens`** — cumulative counters reset at each new turn, summed from `ModelEvent::Usage` events the providers emit per agent-loop step.
- The streaming line was previously `Working (770s • esc to interrupt)`. It's now `Working (12m 50s · ↓ 26.3k tokens · esc to interrupt)` matching Claude Code's display style. Token block is hidden when `turn_output_tokens == 0` (the cumulative is still 0 for the first hundred ms before usage events fire).

### Added — Todo list (`todo_write` tool + TUI rendering)

- **`src/tools/todo_write.rs`** — new tool. Schema: `{todos: [{subject: string, status: "pending"|"in_progress"|"completed"}]}`. Each call REPLACES the active list. Validates: ≤50 items, ≤120 chars per subject, exactly one in_progress at a time, no empty subjects.
- **`AppEvent::TodoUpdate(Vec<Todo>)`** — fired on every `todo_write` call so the TUI can re-render. App.todos cleared at each new turn so stale lists from the previous turn don't bleed through.
- **`render_todo_list` in chat.rs** — renders the active list under the transcript with a `★ Tasks (done/total done)` header. Items render with status glyph (`☐` pending, `▶` in_progress, `☑` completed). The active in_progress item is bold + accent-colored; completed items are dimmed and struck-through; pending items are muted.
- 6 todo_write tests cover happy path, multi-in-progress rejection, empty-subject rejection, overlong-subject rejection, missing-todos-array rejection, and the "empty list = clear todos" semantics.

### Changed

- `LocationView` gained a `preview: Option<String>` field for references rendering. `definition` / `implementation` / `type_definition` populate it as `None`; `references` populates it from disk via `read_line_at`.
- `LspAction` enum: 8 new variants (References, Implementation, TypeDefinition, DocumentSymbols, WorkspaceSymbols, Diagnostics, Rename, CodeActions). `LspAction::is_mutating()` helper for permission classification.
- `ToolContext` gained `lsp_writethrough: bool` and `lsp_diagnostics_timeout_ms: u32` for the writethrough hook. `AgentLoopConfig` and `ProviderRequest` got matching fields so the values flow through the layered config from global TOML → App → ProviderRequest → AgentLoop → ToolContext.
- Test ergonomics: every test fixture that builds a `ToolContext` now sets the new fields explicitly. Saves wiring boilerplate from leaking across the codebase.

### Notes

- 240 lib tests pass (was 200, +40). 8 integration tests + 2 LSP integration tests against real rust-analyzer still pass. `cargo build`, `cargo clippy --all-targets -- -D warnings`, and `cargo fmt --all -- --check` all clean.
- Bumped 0.5.0 → 0.6.0 across `Cargo.toml`, `Cargo.lock`, `npm/src/package.json`, `npm/src/package-lock.json`, `npm/package-lock.json`, install scripts, and the README release example.
- The freemodel relay, R2 distribution, friendlier `<os>-<arch>` archive naming, the helix-derived `defaults.toml` registry, and the `lsp` tool's N1 surface all carry forward unchanged.
- Phase plan from `docs/spec/lsp.md` is now fully shipped — N1 (v0.5.0) + N2 + N3 + N4 (this release).

## [0.5.0](https://github.com/lucasram20/artui/compare/v0.4.0...v0.5.0) (2026-05-31)

First LSP release. Phase N1 of the four-phase Language Server Protocol roadmap (`docs/spec/lsp.md`, `docs/archive/todos/phase-n*-lsp-*.md`): a Tower-based async-lsp client wired into the tool loop, a vendored ~190-server registry sourced from helix-editor's `languages.toml`, and a single `lsp` tool with three actions — `definition`, `hover`, `status`. The agent can now ask "where is `Foo` defined?" or "what's the type of this expression?" and route through a real language server (rust-analyzer / gopls / pyright / typescript-language-server / clangd / …) instead of grep + Tree-sitter heuristics.

Phases N2 (read-only completeness — references, diagnostics), N3 (writethrough on `apply_patch`), and N4 (rename, code_actions, applyEdit) are still open. See the phase tickets for shape.

### Added

- **lsp(skeleton):** new `src/lsp/` module with `client.rs` (one `LspClient` per `(server_id, root)` — owns the child process, async-lsp `ServerSocket`, capabilities cache, diagnostics map, and a `Drop` that sends `shutdown` + `exit` so child processes never orphan), `manager.rs` (`LspManager` — `Arc<RwLock<HashMap<…>>>` cache, lazy spawn-on-demand via `for_path`, cancel-safe `warmup` background task, graceful `shutdown` that walks all clients), `registry.rs` (`ServerRegistry` — parses bundled defaults plus user overlay at `~/.config/artui/lsp.toml`, `resolve(path) -> Option<(server_id, root)>` driven by extension lookup + root-marker walk with deepest-match preference, falls back to cwd when no markers match), `render.rs` (LSP `Location` / `Hover` payloads → strings the model can act on, capped at 8 location hits, markdown fences stripped from hover by default), `types.rs` (`ServerSpec`, `LspAction`, `LocationView`, `HoverView`).
- **lsp(registry):** `src/lsp/defaults.toml` — 191 server entries vendored from helix-editor's `languages.toml` (MPL-2.0) by `scripts/sync-helix-lsp.py`. Covers rust-analyzer, gopls, pyright, basedpyright, pyrefly, ruff, typescript-language-server, deno, clangd, zls, taplo, elixir-ls, gleam, nimlsp, dart, kotlin-language-server, lua-language-server, bashls, vimls, hls, ocaml-lsp, sourcekit-lsp, terraformls, ansiblels, yaml-language-server, jdtls, omnisharp, scalameta, perlnavigator, marksman, prismals, graphql-language-service, and ~150 more. Curated `EXTRA_BINDINGS` in the script add file-type / root-marker bindings for servers helix declares without a default language binding (pyright, deno, ruff, basedpyright, pylyzer, pyrefly).
- **lsp(sync-script):** `scripts/sync-helix-lsp.py` — pure-stdlib (Python 3.11+ for `tomllib`), pulls upstream `helix-editor/helix:languages.toml`, transforms to artui's flat `[server.<id>]` schema, hand-emits deterministic TOML. Re-running the script against the same upstream commit produces a byte-identical file (verified). License compliance documented in `src/lsp/NOTICE` per MPL-2.0 §3.
- **tools(lsp):** new `src/tools/lsp.rs` — `Tool` impl with three actions. `definition`: 1-based line/column, returns one `path:line:col` per hit (≤8 hits). `hover`: returns plaintext-stripped contents capped at 4 KB. `status`: lists running servers with `[ready]` / `[initializing]` markers and workspace-relative roots. Capability gating per request — server that doesn't advertise the action returns "server `X` does not advertise `Y` capability" instead of hanging. Path normalization via `lsp_types::Url::from_file_path` end-to-end (no manual `file://` strings, Windows-safe). Read-only ops bypass the approval engine — same semantics as `read_file`.
- **config:** new `[lsp]` table in `~/.config/artui/config.toml`. `enabled = true` (default), `warmup_on_startup = true`, `log_messages = false`, `request_timeout_secs = 10`. `[lsp] enabled = false` removes the tool from the registry entirely; the model never sees it. User-supplied server overrides live at `~/.config/artui/lsp.toml` and merge over the defaults — same overlay shape as `config.toml`.
- **app:** `App` gains `lsp_manager: Option<Arc<LspManager>>`. `ToolContext` gains `lsp_manager: Option<Arc<LspManager>>` so any tool can dispatch through the manager. `AppEvent::LspDiagnostics { server_id, path, count }` so `publishDiagnostics` notifications surface in the status footer.
- **deps:** `async-lsp = "0.2"` (features: `client-monitor`, `omni-trait`, `stdio`, `tokio`, `tracing`), `lsp-types = "0.95"` (matches async-lsp's re-export), `tokio-util` gains the `compat` feature for the AsyncRead/AsyncWrite shim, `tower = "0.5"` for the Tower service stack inside async-lsp's `MainLoop`. Release binary grows ~600 KB; tarball goes from ~4 MB to ~4.6 MB.

### Changed

- **tools(registry):** `ToolRegistry::with_lsp_tool()` registers the `lsp` tool. Called from `lib.rs` after constructing the manager. Subagent registries (`for_subagent`) intentionally do not get the `lsp` tool — only the primary agent surfaces LSP, matching the same boundary used for `apply_patch` and `shell`.
- **agent(loop):** `AgentLoopConfig` gains an optional `lsp_manager` so the agent loop can thread the manager into every `ToolContext` it builds. `None` keeps legacy behaviour for tests.

### Notes

- 200 lib tests pass (was 166 — 34 new across registry resolution, `for_path` idempotency, missing-executable error shape, render formatting, hover markdown stripping, status snapshot, action enum parsing, and capability-gated tool dispatch). 8 integration tests still pass. `cargo build`, `cargo clippy --all-targets -- -D warnings`, and `cargo fmt --all -- --check` all clean.
- **Process leak prevention:** `LspClient::spawn` sets `kill_on_drop(true)` on the `tokio::process::Command`; `LspClient::Drop` sends `shutdown` + `exit` best-effort, then the child is reaped on `Drop`. A panicking artui cannot orphan a `rust-analyzer` (or any other server) child.
- **Server discovery:** users still install language servers themselves (`rustup component add rust-analyzer`, `go install golang.org/x/tools/gopls@latest`, `npm i -g typescript-language-server`, etc.) — artui doesn't bundle them. When a server isn't on `$PATH`, calling `definition`/`hover` on a matching file returns "language-server executable `<cmd>` not found on $PATH; install it to enable LSP for `.<ext>` files" instead of hanging or crashing.
- **R2 mirror + relay:** the freemodel relay, R2 distribution, and friendlier `<os>-<arch>` archive naming from 0.4.0 carry forward unchanged. Tag-driven release flow unchanged.
- Bumped 0.4.0 → 0.5.0 across `Cargo.toml`, `Cargo.lock`, `npm/src/package.json`, `npm/src/package-lock.json`, `npm/package-lock.json`, the install-script header comments, and the README release example.

## [0.4.0](https://github.com/lucasram20/artui/compare/v0.3.10...v0.4.0) (2026-05-31)

Patch release with two changes: a fix for Windows `latest`-resolution in the install script, plus a friendlier publish format for release archives so the GitHub release page no longer reads as `*-unknown-linux-gnu` to anyone not steeped in Rust target triples.

### Fixed

- **install:** `scripts/install.ps1` captured the wrong version from the R2 `latest/checksums.sha256` file because the optional pre-release-suffix branch in the regex (`(?:[-+][0-9A-Za-z.\-]+)?`) was permissive enough to extend across the version-arch boundary in archive names like `artui-0.3.10-aarch64-apple-darwin.tar.gz` — it captured `0.3.10-aarch64-apple` instead of `0.3.10`. The script then built an asset URL that didn't exist on R2, missed the mirror, and the GitHub fallback 404'd against the private repo.
